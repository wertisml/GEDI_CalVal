0.1 Plot and Tree Survey Data

  • The objective of this notebook is to go over the steps needed from start to end to get your plot and tree inventory data structured correctly for creating simulated waveforms over GEDI footprint-sized subplots.
  • The steps illustrated in this notebook are just a single example of an approach used for this specific site, every site is different and will require different methods, but the end result of every site should result in a standardized result that will be easily carried over to the second step and eventually, seamlessly fit in with a larger collection of sites.
  • Overall we are taking steps towards turning your plot into 25m by 25m subplots where all the trees within an individual subplot are correctly pooled together.
  • The steps needed to accomplish this objective can be broken down into 10 key steps

1 Starting Your New Project

Setting up your project folder for the first time.

  1. On the command line navigate to the /renv directory within the docker and type R, this will open R on the command line, now set the working directory as the GEDI_CalVal folder, setwd("/workspace/GEDI_CalVal").

  2. Type system(command = "Rscript scripts/createProjectDirectory.R {Your directory name}"), this will create a new folder in the /data folder containing the name that you supplied along with 5 CSV files that we will be filling out and a R script named dataManipulate.R, you can close R and you do not need to save the image.

  3. Inside the newly created project directory create an additional folder called /metadata to store your original versions of the data.

  4. Make a copy of your tree and plot data, naming them treeData and plotData, ensure that they are in CSV format and put them in the main folder (not in metadata).

2 Filling out dataMatchColumns.csv

Defining the variables used in your data and any name changes that need to be made.

  1. We will start with the dataMatchColumns.csv file. Open this file, the initial file will contain only the following headers var_in, method, unit_in, var_out, notes.

  2. Follow the variableDefinition.csv (found in the /config folder of the gedicalval directory) variable and units column to ensure your columns match the desired name and format. There is a description column if you are unsure of what to rename your variable.

  3. var_in are the column names that you have in your original plotData.csv and treeData.csv, you will need to supply the name of every column header from both files in the var_in column, be carful to ensure that everything matches exactly.

  4. The column method is used when the units that you use are different than the required units which are notated in the variableDefinition.csv file. If this is the case, in the same /config folder is a file called variableConversion.csv that you will supply the “conversion” value to, otherwise fill in the cell with NA.

  5. The unit_in column is filled out with the units that your original dataset used, if your variable is unitless use NA, the variable abbreviation that is needed is supplied in the variableDefinition.csv file under the header units.

  6. The var_out column has the variable names from variableDefinition.csv that correspond with your original column names. If your initial column name matches the required column name, you still need to supply that name.

  7. The notes column is there to help you keep tract of what you are doing, there is no need to fill this in with information, however, you need to supply NA to every cell that you do not have anything in them.

3 plotDataImportOptions.csv & treeDataImportOptions.csv

How R should handle reading in your data.

  1. These two files are very similar and only require a few potential changes.

  2. If your data has headers (i.e., column names) leave as TRUE.

  3. For the 4th row, separator, you need to indicate how your CSV file indicates when a new cell begins, if you are unsure, open your CSV file using notepad, most commonly a “;” is used to separate data, but be sure that this is the case for your data.

4 dataNew.csv

Variables missing from your data that need to be included.

  1. This file has a similar effect as dataMatchColumn.csv but allows for additional information to be added that might be missing from the original data.

  2. You will fill out newVariable for the variable name and newValue for the value that you want to give the variable.

  3. In situations when you need to make minor changes to the data that you do not want to handle in the dataManipulate you can handle here as well. For example if you need to change the pft.name for each plot in the data you can add plot under the lookupVariable header, the plot number under lookupValue, the column name under newVariable, and the value you want it to have under the newValue column.

  4. Keep in mind that this is applied post dataManipulate.R has been run so the newVariable value needs to match the standardized version we use instead of the original name.

  5. Make sure that any cell that does not have information in it has NA in the cell.

9 Manipulate

Creation of subplots and correct assignment of trees to associated plots.

This step uses a combined treeData.csv and plotData.csv and the join step takes place during the makeGEDICalVal script, but to make sure your steps work correctly you can join your plotData.csv and treeData.csv together after you have tested them in their individual manipulate functions.

9.1 If you created the p.geom values during the manipulate_plot step you can skip the next step.

  1. If you have a shapefile of the plots read them in using the function vect(). Now we will need to create subplots diving up the larger plot to match the dimensions of a GEDI footprint. To accomplish this we will use the function polygonchopper(). This function requires an understanding of the plot data and is run in a mapply() function so that each plot is run separately. I will attempt to breakdown how to set up this function but again this will vary based on your data. For this function, you will need to supply 7 different values.

    • polygon: this is comprised of the individual plots that make up the shapefile, you may only be concerned with a few of the total plots in which case you will need to subset the data, but assuming you are using every geometry in the shapefile you can use lapply(seq_len(nrow(shape)), function(i) shape[i, ]) with shape being the name of the shapefile.
    • ID: This should be the unique identifier that distinguishes every plot apart from each other and should be in data frame format.
    • PlotStatus: This has the value of plot or subplot status of the individual geometries, if this is not already in the shapefile data you will need to supply it in the function through the use of a list or prior to this function.
    • Start_side: this informs the function on how it will move through the geometries and is also supplied in the form of a list.
    • Dimension: This should be the same regardless of the plot and should be a value of 25, representing the diameter of the GEDI footprint.
    • asGrid: This should remain as TRUE
    • proj4string: this is the crs that will be used on the final output, this should have the same crs as the shapefile, you can use crs(shape) to automate this.

The result of this function is a list of spatialVectors one for each geometry in the data, we will call shape_gedi. Make sure to remove any empty spatialvectors from the list, then combine the list creating a single spatialvector. To ensure only complete subplots are retained you will need to compare the original shape to the output of the polygonChopper.

Code 
# This is only to allow for the polygonChopper work flow to be demonstrated.

Code

# Divide plots in shapefile into GEDI footprint size rectangles so that when subplot is aggregated with full plot biomass is unique for each footprint
shape_gedi <- mapply(FUN=polygonChopper, polygon = lapply(seq_len(nrow(shape)), function(i) shape[i, ]), 
                     ID = as.data.frame(shape)$FullId, 
                     PlotStatus = as.data.frame(shape)$PSFlag, 
                     start_side = rep("topright",40),
                     MoreArgs = list(dimension=25,  asGrid=T, proj4string = crs(shape)))

shape_gedi <- shape_gedi[!unlist(lapply(shape_gedi, rlang::is_empty))]
# Combines all elements of the list into a single spatial vector
shape_gedi <- do.call(rbind, shape_gedi)
# Create an unique ID for each plot

  • Once you have finished the steps above you will return to the command line and just like the system(command = "Rscript scripts/createProjectDirectory.R") you will run R, setwd("/workspace/GEDI_CalVal/"), system(command = "Rscript scripts/makeGEDICalVal.R -b -i {your directory}""). This will take a while to run and if there are any errors there will be an error message in the command window indicating what function caused the script to fail, if the script failed to compile and no error message was given, check the scripts in the /R folder, primarily, geometry.R and postprocess.R and make sure there is a function named browser() that is not commented out for each function, this will tell you which function failed. However, when using the functions not from the command line you will want to have the browser() functions commented out (i.e., #). The issue will not be in the R scripts that hold the functions that are used but rather in the dataManipulate.R script, the error message will indicate which function on your end was not set up correctly, it is then up to you to identify the location of the error in your script and attempt to fix whatever was wrong.
